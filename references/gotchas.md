# Scout Gotchas

Full list of non-obvious issues and environment-specific facts for Scout. Read this before running Scout in a new environment or debugging a surprising result.

- **Tier 3 sources require explicit permission** — Paid OSINT providers and background databases (Tier 3) cannot be queried without a recorded PermissionGrant. The skill will silently skip Tier 3 even if credentials are configured.
- **User relevance defaults to `agent_only`** — Signals emitted to Chronicle default to `user_relevance: "agent_only"` unless the user explicitly requested the research or the entity connects to a known `user` Chronicle entry. This means most Scout entities won't be promoted.
- **Hard cap at 2 Sherlock passes** — Recursive handle discovery is allowed for exactly 1 additional pass (2 total), including sweeping maigret‑reported ‘other IDs’ as additional handles (ID‑pivot). Further recursion is silently blocked regardless of leads found.
- **Identity gate requires 2+ data points** — A username match alone produces only `unverified_lead` status. Profiles are `verified` only when 2+ seed data points overlap (name + location, etc.).
- **A handle manufactured from the contact's own name cannot corroborate that name (circular anchor)** — When `handle_origin == "name"` (or a pivot is harvested from a name-derived seed), maigret profile name-matching is zeroed: pivot and check are the same signal, so every namesake passes. Pass `enable_recursion=False` (CLI `--no-recursion`) to skip the pivot sweep entirely; otherwise capped at 2 handles and every harvested handle still faces the gate, with taint propagating from its seed.
- **minimize_pii suppresses home addresses and personal details** — When the user sets `minimize_pii=true`, the final brief suppresses unnecessary sensitive details even if they were found during research. Re-run without the flag to see full data.
- **"Not subscribed" ≠ broken on RapidAPI.** Many APIs return tools on `tools/list` but "You are not subscribed to this API" on actual calls. These are tier-gated by the provider, not broken. 3 genuinely broken LinkedIn APIs (linkedin-data-api, linkedin-api8, li-data-scraper) — provider shut down. 4 new ones work: fresh-linkedin-scraper-api (primary), linkedinscraper, linkedin-email-finder5, linkedin-lead-enrichment.
- **`gh api` base64 content is unreliable for counting** — `gh api repos/<owner>/<repo>/readme --jq '.content' | base64 -d` can silently return truncated or empty results. For fetching raw GitHub README content, use `curl -s "https://raw.githubusercontent.com/<owner>/<repo>/<branch>/README.md"` instead. This returns clean text that `wc -l` and `grep` can process directly.
- **Branch names vary across repos** — `jivoi/awesome-osint` uses `master` (not `main`). Always verify branch name with a quick `curl -s -o /dev/null -w "%{http_code}"` probe before fetching content.
- **curl timeout for unreliable endpoints** — Some GitHub endpoints return 0 bytes under rate-limiting. Use `--max-time 15` and check HTTP status code before processing output.
- **Public-records scripts use stdlib only** — All fetch scripts in `scripts/fetch_*.py` use Python stdlib only (no pip installs required). They use `urllib.request` with retry logic and respect `Retry-After` headers. 429 responses surface immediately with the upstream's quota message.
- **JEV identity adjudication is demote-only** — When only one profile matches the identity gate, JEV is consulted to distinguish same person from namesake (demote-only, fail-open). JEV can only lower the identity level (e.g., `med` → `low`); it cannot create a match or raise the level. No JEV key, timeout, or malformed response leaves the rule-based verdict untouched.
- **ICIJ offshore leaks cache** — First run downloads ~70 MB bulk CSV. Cached for 30 days under `$HERMES_OSINT_CACHE/icij/` (default: `~/.cache/hermes-osint/icij/`). Subsequent runs search the local cache.
- **Entity resolution is token-bag only** — `entity_resolution.py` does NOT use external fuzzy libraries (no rapidfuzz, no jellyfish). Token-bag matching is the upper bound. For Levenshtein, transliteration, or phonetic matching, pip-install separately.
- **Statistical significance ≠ wrongdoing** — `timing_analysis.py` p < 0.05 means the timing pattern is unlikely under the null. It does not establish corruption. Always state this in the brief.
- **TinyFish f-string quoting trap** — When generating Node.js scripts via Python f-strings, JavaScript template literals containing `${...}` get mangled by Python's f-string interpolation (Python tries to evaluate `{...}` as a Python expression). Write scripts using string concatenation (`f.write(...)`) instead of f-strings, or escape with `{{` and `}}`. Symptom: generated script has quotes around JavaScript expressions, causing `page.evaluate` to receive a string literal instead of code.
- **playwright-core module resolution in temp files** — Node.js scripts executed from `/tmp` or `/root/.hermes/cache/scratch/` cannot resolve `playwright-core` via `require('playwright-core')` because node_modules is in the scripts directory. Use the absolute path: `require('/root/.hermes/profiles/indigo/skills/ocas-weave/scripts/node_modules/playwright-core')`.
- **TinyFish session cleanup** — Always close TinyFish sessions after use (`tinyfish browser session close <session_id>`) to avoid resource leaks. The stealth browser sessions cost ~$0.002/minute. Auth-walled platforms (LinkedIn, Twitter/X, Facebook, Instagram) serve auth walls to anonymous TinyFish sessions — identity verification via `_names_match` is required before accepting any extracted data, and extracted images may be generic/auth-wall images, not verified person photos.
- **TinyFish identity verification is mandatory** — For auth-walled platforms, extracted profile data (name, picture URL) must be verified against the contact name using `_names_match()` before acceptance. LinkedIn serves generic/auth-wall images even when the profile name matches — the image is NOT verified as the person's actual photo. Reddit returns base64 SVG placeholders, not real avatars. X/Twitter, Instagram, and Facebook extraction is implemented but not fully tested in batch mode.
- **Sift auth-walled fetch upgrade** — `sift_extract_from_pages()` in `weave_enrich.py` now uses `fetch_via_tinyfish()` for auth-walled URLs (LinkedIn, Twitter/X, Facebook, Instagram, TikTok) instead of falling back to title+snippet only. This provides actual page content for LLM identity verification and fact extraction. The fetch is gated by `max_pages` budget to avoid excessive TinyFish session costs (~$0.001/contact).
